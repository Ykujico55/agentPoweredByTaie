# 宿主生成的源码引用

本功能让程序生成源码片段编号，模型只选择编号。报告中的文件名、行范围和代码均从本次证据目录展开。它检查引用归属与快照版本，语义正确性单独记录为 `not_checked`。

## 当前入口

先在独立 SQL 实验中使用，不改变日常 `/review`，也不改冻结的 v2/v3 实验。选择 G–L 中的一个案例，读取已有真实分析快照，发起一次无工具模型请求：

```powershell
npm run test:sql:citations -- ".taie-agent/sql-heldout/2026-11-03T11-52-38-347Z-6deaf3f7/result.json" J
```

命令使用原协议中的模型配置和已配置凭据，会产生 API 用量。每次运行只请求一次、不重试、不重新构建项目或运行 Tai-e。历史分析文件必须仍存在且通过哈希检查。

输出位于 `.taie-agent/source-citations/<运行ID>/`：

| 文件 | 内容 |
| --- | --- |
| `catalog.json` | 宿主生成的编号、文件、原始文件哈希、行范围和代码 |
| `input-manifest.json` | 原始输入版本、新旧请求正文哈希、目录哈希 |
| `request.json` | 实际系统提示和用户证据，保留完整交互输入 |
| `result.json` | 原始回复、规范化建议、引用校验、耗时和用量 |
| `report.md` | 中文解释，以及由宿主展开的对应源码 |

## 实现

1. 复用已有输入加载器核验历史报告、相关源码与策略；不读取当前可变项目。
2. 检查模型可见源码内容与原始文件哈希一致。若脱敏改变了内容，则停止，不重新填回被脱敏的值。
3. 按文件顺序每 8 行生成一个片段，编号绑定整份目录的内容版本。保留全部选中文件，不按标签挑选代码。
4. 模型按解释项返回 `text` 和 `sourceIds`。源码位置和引文不属于可提交的结构化字段。
5. 宿主精确解析 ID，并在请求结束后复查原始输入未变；没有模糊匹配或自动纠正编号。
6. 报告为每个解释项展开源码，保留未知编号和没有引用的解释项。

例如模型返回：

```json
{
  "text": "两个分支都将固定查询写入被读取的数组元素。",
  "sourceIds": ["src:本次目录版本:2", "src:本次目录版本:3"]
}
```

示例编号只是格式说明；真实编号来自本次请求中的 `sourceCatalog`。模型仍保留 assessment、ruleClaim、evidenceRefs、coverage、assumptions 和 missingEvidence 字段，原来的 rationale 改为 claims 数组。其余分类与证据范围规则复用原解析器。

## 结果含义

| 引用状态 | 含义 |
| --- | --- |
| `matched` | 已提交的所有编号属于本次目录，输入版本未变 |
| `invalid` | 至少一个编号不存在，保留具体未知编号 |
| `missing` | 没有提交任何源码引用 |
| `stale` | 原始输入或本次实现版本发生变化，校验结果失效 |

部分解释项没有源码引用时，报告单列其序号；其他编号匹配不能给未引用部分补分。关于测试计数、策略或证据缺失的解释可以不引用源码。

目录记录原始文件 SHA-256；片段只将 CRLF 统一为 LF，保留缩进、字符串内部空白和真实空行。当前使用固定 8 行片段，不解析 Java 方法或语句边界；跨片段的解释可以引用多个编号。

“编号匹配”只确认展示的代码来自本次快照。模型仍可能选择不相关片段、误解分支条件，或在正文写出错误事实。报告中的模型正文保留为模型解释，`semantics: not_checked`，没有自动排除告警或改变原检查状态。

## 2026-11-17 功能验证

类型检查通过；宿主测试 154 项通过、1 项因符号链接权限跳过、0 失败。新增 5 项测试覆盖行号与空白、原始内容哈希、宿主渲染、错误/旧版本编号、未引用项和过期输入，并验证错误解释也只能获得引用匹配结果。

对案例 J 发起一次真实 DeepSeek 请求，无重试。宿主提供 CaseJ/Main 全文的 9 个片段，模型返回 6 条解释，引用 4 个不同编号，全部匹配。第 5 条讨论分析报告而未引用源码，报告将其单列。流程耗时 15.85 秒，SDK 总用量 5,018 token。

独立核验确认全部 9 个片段的文件、行范围和内容与历史源码一致，6 个原始输入文件及冻结的 v2/v3 未变。原检查仍为 findings、6 条告警保留、review 为 not_run。

另行核对源码时发现第一条解释的顺序错误：模型说两个分支都先写 slots[1]，实际负数分支先写 slots[0]。这条模型原文完整保留，另存 AI 观察记录；引用层没有把它认证为正确。这次只验证引用功能，不计为新的分类或解释准确率评测。
