# 六例受委托复核与 v3 回归

2026-11-17，用户委托 AI 完成 G–L 的源码复核与标注，并继续下一步开发。本轮交付包含独立路径论证、逐项解释标注、真实 H2 重放，以及新提示的一轮回归。标注作者为 AI，`humanReviewed: false`。

**结论：复核与标注已完成，v3 未通过解释质量验收，不替换日常复核版本。** 六次分类都正确，但只有 G 的整份解释全部事实获支持。H/I/J/K/L 均出现错误或无依据的事实断言。

## 六例的分类依据

| 案例 | 标注 | 决定性依据 |
| --- | --- | --- |
| G | 真缺陷 | `mode<0` 直接传入输入；`mode>1` 且为偶数时，经 `route` 返回输入。0、1 和大于 1 的奇数走常量路径。 |
| H | 误报 | 污染赋值要求 `mode<-1` 或 `mode>2`；SQL 执行要求 `0<=mode<=2`，条件互斥。 |
| I | 真缺陷 | 两个 `new Box` 是不同对象。负数只污染 second；非负数在第一轮就污染 first，SQL 读取 first。 |
| J | 误报 | 两个分支都只把输入写进数组下标 0，下标 1 始终写常量，SQL 只读取下标 1。 |
| K | 真缺陷 | `mode=1/2` 保留输入；`mode=0` 在 switch 后被常量覆盖，其他值走默认常量。 |
| L | 误报 | 正常路径与两个已捕获异常路径都经过 finally，它在 SQL 执行前覆盖同一字段。 |

这里的缺陷指固定查询业务前提下，外部输入到达配置的 SQL 执行参数。安全路径的结论来自完整代码论证。独立重放在 H2 中执行了 54 个边界输入，覆盖负数、0、1、2、奇偶分支和 int 极值；全部实际 SQL 与结果行数符合上述判断。

旧回复 G/I/K 的路径错误得到确认。K17 的旧标注只评了复合句后半句，本轮补记前半句忽略覆盖的错误，并与 K14 的同一语义错误去重。

## 最小开发改动

新增 [v3 实验提示](../evaluations/sql-regression-v3/system-prompt.txt) 与 [冻结协议](../evaluations/sql-regression-v3/protocol.json)。它在 v2 后增加路径核算要求：保持条件一致，区分对象和数组位置，跟踪 sink 前最后一次写入，区分抽象图与源码执行，核对引用位置。返回协议仍为原来的八个字段。

[回归脚本](../scripts/review-sql-regression.ts) 复用同一历史输入和原有模型调用、解析与评分接口。每条实际告警请求一次，不重试；期望标签、测试源码与独立重放没有发送给模型。G–L 已用于本轮提示开发，因此其用途为 regression。生产 `/review` 沿用既有版本。

```powershell
npm run test:sql:regression -- ".taie-agent/sql-heldout/2026-11-03T11-52-38-347Z-6deaf3f7/result.json"
```

| 指标 | v2 原回复，经本轮复核 | v3 新回复 |
| --- | ---: | ---: |
| 分类正确 | 6/6 | 6/6 |
| 真缺陷被建议为误报 | 0/3 | 0/3 |
| 去重事实获支持 | 112/116，96.6% | 135/151，89.4% |
| 错误 / 无依据事实 | 4 / 0 | 14 / 2 |

| 预定关键事实获支持 | 14/18 | 14/18 |

两次各运行一轮，结果描述这六例的实际表现。v3 增加了正确路径说明，也增加了错误的行号、方法属性及附加断言，未达到预先冻结的“6 份解释全正确、18 个关键事实获支持”目标。事实数量不同，因此同时保留整份解释指标和关键事实覆盖。

| 案例 | v3 事实：正确 / 错误 / 无依据 | 具体问题 |
| --- | ---: | --- |
| G | 22 / 0 / 0 | 负数、正偶数与常量分支说明一致。 |
| H | 23 / 0 / 1 | 核心互斥论证正确，但断言“测试……不涉及此无关路径”；请求只含测试计数，没有测试内容。 |
| I | 30 / 1 / 0 | 已解释负数与 1 互斥，后文却又在负数分区内把 `mode==1` 当成可行路径。 |
| J | 19 / 3 / 0 | 把第 15 行赋值写成第 13 行；把 public 的 execute 说成 private；引用不存在的节点名。 |
| K | 23 / 9 / 0 | 多处源码位置错配；同一回复先说 `mode=0` 污染到达 sink，后又正确说明它被覆盖。 |
| L | 18 / 1 / 1 | 把第 23 行 catch 声明当成覆盖赋值；没有证据支持所称的“路径敏感”分析属性。 |

例如 K 的实际代码先让 `mode=0` 穿透 case 1，随后 `if (mode == 0)` 成立并写入常量。模型先说这个 if 为假，后面又说它覆盖了污染值。最终“有真缺陷”的分类仍正确，因为 `mode=1/2` 确实保留外部输入；这不能使前面的错误路径成立。

新回复共抽取 164 条引用，去重为 151 项事实。主张的重复、相互矛盾、位置与行为的拆分均有逐项理由。J 提到了固定下标，但遗漏“新数组且不逃逸”这一预定关键事实的组成部分，因此不给完整锚点分；遗漏不另算事实错误。

原 v2 文件保持不变。本轮修正另存于 `v2-reviewed/`，补齐 K17 前半句的抽取后仍为 112/116。冻结评分器的 JSON 沿用 `provisional / humanApproval: pending`，表示没有人类签收；本次受委托的 AI 标注状态单独记录为 `completed`，没有未完成的用户标注任务。

## 下一步
