# Tai-e Coding Agent 产品规格

确认日期：2026-11-03。本文记录用户对 44 项需求问题的回答，以及随后接受的 7 项收敛决定；发生冲突时，以后者为准。本文定义后续产品目标，当前原型的可用功能见 [README](../README.md)，实施顺序见 [开发与验收计划](development-plan.md)。

## 产品目标

面向 Java 开发者，一次编码任务应能走完以下循环：**① 模型编写代码 → ② 宿主运行 Tai-e 自检 → ③ 提取项目告警 → ④ 模型只读核对告警 → ⑤ 依据证据定位真实问题 → ⑥ 模型按修复配置修改代码 → 回到 ②；⑦ 宿主独立验收通过后结束。** 检查中复用项目的实际构建和测试。开发优先补齐影响这条循环的环节。首版沿用 Pi，检查和验收由宿主控制。

待验证的产品假设是：与使用相同基座模型的普通 agent 相比，Tai-e 反馈与复核能降低 token 消耗并提高任务成功率。完整评测同时记录耗时和人工投入，不能把人工接管造成的 token 下降解释为系统整体提效。

## 已确认的范围与取舍

| 决策 | 产品约束 |
| --- | --- |
| 主评测方向 | 首轮聚焦 SQL 注入污点分析，明确 source、sink、sanitizer 和支持模式。保留已有检测器及其回归案例，不先扩充检测器数量。 |
| 分析保证 | 暂不承诺 soundness；公开具体分析的范围、假设、限制和实测结果。有精确定义和充分依据后，才单独声明某项分析的保证。 |
| 告警权限 | 所有严重等级均由模型提出建议、人类决定处置。模型可以排序，不能自动关闭、隐藏或删除告警，也不能决定 CI 放行。 |
| 误报证据 | 证据必须覆盖被排除告警成立的全部相关可能性。证明某一条抽象路径不可行，不等于证明整个告警是误报。 |
| 接入顺序 | 第一阶段为 JDK 17、单模块 Maven 和一种明确的隔离环境；后续依次接入 Gradle、有限 Spring 模型。 |
| 比较口径 | 固定共同任务描述、基座模型、共同工作规则和可比预算，显式记录各组工具及说明差异；统计全部尝试和人工成本。 |
| 数值门槛 | 先用开发集确定支持规模、预算和性能门槛，再冻结最终评测。未测量前不声称支持大型项目或已取得成本收益。 |

现有基础检测器为 `dropped-exception`、`clone-idiom` 和 `dead-code`；源码扩展包含修复后的 `null-pointer` 与新增的 `division-by-zero`。污点分析需配置入口与策略。整数除零目前覆盖过程内可确定为零的整数除数，空指针检测存在字段读取和跨方法返回等限制。框架拥有指针分析，不等于每个检测器都使用了完整过程间分析。参见 [分析入口](../src/taie.ts)、[除零实现](../vendor/Tai-e/src/main/java/pascal/taie/analysis/bugfinder/DivisionByZero.java)、[空值传播实现](../vendor/Tai-e/src/main/java/pascal/taie/analysis/bugfinder/nullpointer/IsNullAnalysis.java)。

## 项目与执行边界

首阶段通过真实 Maven 构建取得 classpath、编译产物和项目测试结果，感知注解处理器。分别记录编译 JDK、测试 JDK、Tai-e 运行 JVM 和被分析标准库；目标为 JDK 17，`--release 17` 不能替代运行库匹配。

生成代码默认不展示其自身告警，但保留必要的编译产物及分析关系；报告展示过滤必须与分析输入排除分开记录。依赖或生成代码缺失影响分析时，标记覆盖不足，不能把相关业务代码判为已检查通过。

后续 Spring 支持限定于注解和显式注入关系。反射限定于已验证的常量模式，例如 `Class.forName` 字面量及类字面量；native 内部属于分析边界。多模块跨模块分析、动态代理、变量反射和 JNI 内部暂不支持。发现不支持特征时明确记录；未发现某种特征不构成不存在该特征的证明。

构建插件、注解处理器、项目测试和模型 shell 在隔离环境内运行，限制可见文件、网络、资源和进程权限。工具调用拦截不能替代操作系统隔离。主实现路线为 Linux 容器；Windows 开发环境使用 Docker 的 Linux 容器后端，实际支持以隔离验收为准。隔离环境不可用时不得静默改用本机权限执行项目命令。

依赖获取与项目执行分阶段管理网络权限，记录仓库配置、依赖版本和下载结果。项目执行环境不得获得模型 API 密钥、宿主用户目录或容器管理接口。外部模型上下文默认最小化并脱敏，源码外发和诊断包范围应明确；企业代码、本地模型支持另列兼容范围。

## 自检与验收流程

1. 修改前保存输入快照并建立分析基线，包含已有未提交修改。基线无法建立时记录原因，不能将全部后续告警冒充为新增。
2. agent 按任务修改代码。用户可随时显式触发检查；模型声明任务结束后，宿主执行最终检查。跳过检查必须显示为未检查。
3. 使用项目真实构建流程产生新产物，分别运行项目测试与全项目静态分析，记录每个阶段的状态。构建失败时不产生成功的分析结论。
4. 对比新增、消失、变化、遗留告警，默认聚焦本次修改。告警消失只表示本次配置下未再报告，不自动证明补丁正确。
5. 在固定输入上只读复核，输出证据与建议。修复使用独立的候选补丁流程。
6. 宿主根据构建、分析、测试、覆盖和人工处置记录决定任务状态，不能采用模型自行声明的成功。

最终报告以全量分析为准。增量结果只用于开发反馈、排序或预筛选，不提供额外 soundness 保证。源码、构建配置、依赖、规则、入口、框架模型或相关业务前提变化后，旧结果必须重新验证；无法判断是否相关时，保守标为过期。

结果协议应独立表达构建、分析、测试和复核状态，并包含跳过、覆盖不足、待人工处置、拒绝修复、超时、失败和不支持等原因。具体 schema 与退出码在实现时版本化迁移。CI 明确配置验收条件，跳过默认不放行；没有测试或测试未执行，不能写作测试通过。

## 复核证据与人工处置

保留不可变的原始告警、模型建议和人工处置记录。下列状态必须区分：真实缺陷、误报、接受风险、超出范围、分析不完整和无法判断。规则不适用归入超出范围；业务不调用或接受风险不自动等于误报。待复核、过期和已处置属于流程状态，应与真假判断分开。

| 证据类型 | 允许支持的结论 |
| --- | --- |
| E1 模型解释 | 提供复核方向和排序建议，不足以排除告警。 |
| E2 测试未复现 | 说明已运行用例未触发，不能证明不存在缺陷。 |
| E3 人工确认的可审计前提 | 支持前提范围内的处置；业务排除属于范围或风险决定，不自动证明误报。 |
| E4 经验证的约束或其他充分证明 | 在记录的模型、前提及证明范围内支持判断；只证明单路径时不得扩展为整条告警的结论。 |

等级不能机械代替证据适用性检查。误报处置必须说明规则主张、证明范围、证据来源、适用前提和未覆盖边界；即使具备强证据，首版仍由人类决定处置。通用约束求解器不是首版必做项，不能取得充分证据时保留无法判断。

模型按告警需要获取规则定义、位置、调用者与被调方法、字段读写和别名、类型分派、入口与框架假设、分析策略和路径条件。上下文按需分层获取以控制 token；缺失与判断相关的上下文时应明确不足，不能用模型一致意见替代证据。

复核阶段只读，禁止修改源码、测试、入口和规则来证明原告警为假。处置记录包含审核者、时间、理由、证据范围及输入版本；相关输入变化后标记过期并重新复核。原始结论保留为历史，不追溯改写。

模型置信度未经独立校准只能用于排序。即使后续完成校准，当前产品基线仍不允许模型自动关闭告警；未来若变更权限，需另行修改产品规格。

## 修复与工作区保护

修复分为三个独立步骤：允许在隔离工作区生成候选补丁；展示具体 diff、影响文件及测试和分析结果；用户逐次确认后应用到目标工作区。允许生成候选补丁不等于允许应用补丁。

修复行为依据任务需求、已有契约和独立测试。规范不明时保留问题并列出候选行为，不能自行把异常改为返回空串、零或其他业务结果。模型不得通过删除功能、弱化测试、减少分析范围、改规则或增加抑制来取得通过。

补丁应绑定原始输入、验证产物与批准记录。应用前检查用户已有修改和并行修改，冲突时停止；失败或取消保留候选补丁与诊断。恢复只能撤销本次应用的变化，不能覆盖用户在快照后新增的修改。应用后的输入与已验证候选不一致时必须重新验证。

现有 `repair-mode=ask` 是修复前批准直接改工作区，尚未满足上述流程。未来保留 `auto` 时，只能自动生成和验证候选补丁，不能绕过应用确认；非交互模式没有明确应用批准时保留候选结果。参数迁移需同步 CLI 面板、帮助和机器协议。

## 评测设计

分别评价缺陷检测、告警真假判断、给定线索修复和完整编码任务，不用一个总分替代四层结果。首轮采用 SQL 注入支持子集，其余现有检测器继续做能力回归。数据集角色为：Juliet 用于模式对照，OWASP Benchmark 用于对应 CWE 的检测与真假判断，Defects4J 用于适配范围内的真实缺陷修复，冻结的真实需求用于完整任务评价。

在准备数据时锁定数据版本、标注和工具链兼容性。数据集 fixed 版本不代表整个仓库无缺陷；未标注告警记为未标注或无法判断，不能一律计作误报。争议样例保留不确定状态。

隔离标签、官方补丁、fixed 版本、提交信息及泄漏答案的命名和注释。清理过程应可重放并验证任务语义，原始评分材料留在模型无法访问的环境。按项目和模板家族划分开发、验证和最终测试集，记录公开数据预训练污染风险。

对照组至少包含普通 agent、agent 加原始 Tai-e 反馈、agent 加 Tai-e 与只读复核；检测层另与原始 Tai-e 比较。固定共同任务输入、模型版本和共同工作规则。工具列表及必要使用说明允许不同，但必须保存并公开这些差异。共同资源预算可比，Tai-e 组额外记录分析次数与耗时；不能要求不用 Tai-e 的组执行同样数量的分析。

给定位置和类型、只给位置、自主发现三种输入档位分别计分。保存全部尝试、失败、重试和候选补丁。人工辅助单独记录；有人工介入的端到端结果不能标为完全自主结果。

离线模拟筛选只移除明确建议排除的告警，无法判断、证据不足和未复核告警均保留。保留率和筛选后精确率使用同一保留集合，模型弃权率另报。至少报告以下指标，分母为零时记为不适用：

| 指标 | 口径 |
| --- | --- |
| 任务成功率 | 独立验收成功任务数 / 预先登记的全部任务数；另列支持子集和失败分布。 |
| 误报建议排除率 | 被建议排除的已标注误报告警数 / 全部已标注误报告警数。 |
| 真告警误排除建议率 | 被建议排除的已标注真告警数 / 全部已标注真告警数。 |
| 排除建议中的真告警比例 | 被建议排除的已标注真告警数 / 有确定标签的全部排除建议数。 |
| 真实告警保留率 | 未被建议排除的已标注真告警数 / 全部已标注真告警数。 |
| 建议筛选后的精确率 | 筛选后保留的已标注真告警数 / 筛选后保留的全部已标注告警数。 |
| 完整流程召回率 | 最终识别并保留的目标真实缺陷数 / 全部已标注目标真实缺陷数。 |
| 无法判断与人工投入 | 分别统计未标注、证据不足、模型弃权、人工处置次数和人工耗时。 |
| token 与成本 | 统计所有任务及所有尝试的输入和输出 token、缓存计费口径、费用、分析成本及人工投入；另报总消耗 / 成功任务数。 |

建议筛选指标是模型判断的离线评分，不代表产品自动关闭了告警；人工实际处置结果单独统计。完整公开全部任务、可构建、可分析、支持类别及最终结果的分母，构建失败、超时和不支持不从总任务数中删除。

## 门槛与发布条件

开发集负责测量项目规模、冷启动、依赖获取、全量分析、模型复核、重试和人工等待；分别记录 P50、P95、资源消耗及重复运行波动。依据这些测量锁定支持范围、任务预算和验收阈值，再运行最终测试集。原 QA 中未附来源的精确率、召回率或风险百分比不作为已验证指标或默认发布阈值。

发布前必须具备：明确的支持范围，可复现的主要安装路径，环境诊断，独立修复验证，可重复的评测，错误恢复，陌生用户和未参与开发仓库试用，依赖及第三方许可核查。运行记录应支持基于版本、配置、快照、工具结果、批准和补丁的诊断；模型服务不能固定重放时，明确保留内容和不可重放部分。

已有 Java 集成测试超时仍是待处理问题，见 [验证记录](validation.md)。支持范围内的未解释超时阻止发布；若证据表明确实超出支持范围，须在最终评测前明确边界并继续计入完整分母，不能事后移除失败案例。
