# Tai-e Coding Agent 开发与验收计划

计划基线：2026-11-03，依据 [已确认产品规格](product-spec.md)。各阶段以可重现证据验收；完成开发事项不自动代表性能目标或发布条件已达到。

## 当前优先交付：一次编码任务走完自检修复循环（2026-11-18）

当前 [宿主循环](../src/verification.ts) 已经能在编码和每轮修复后独立运行构建、测试和 Tai-e。遇到项目告警时，宿主目前把报告交给同一编码会话，提示它核对并修复；[独立只读复核](../src/review.ts) 尚未把定位结果交给循环。下一项开发补齐 **③ 发现告警 → ④ 核对 → ⑤ 定位 → ⑥ 定向修改**。

1. 在现有编码任务中复用单告警只读复核，使用本轮检查已有的证据。将告警 ID、源码位置、缺陷触发条件和核对依据一起交给修复步骤。模型建议为误报或证据不足时，保留该告警待核对；同轮其他已定位问题仍可按配置修复。模型在编码会话中主动调用分析工具发现告警时，也应走同一顺序。
2. 沿用现有修复选择和轮次上限。每轮改完回到 ②，对修改后的代码重新构建、运行项目测试并分析。当前 ⑦ 的通过条件是构建成功、至少一项测试实际运行且无失败或错误、分析完成且项目告警为零。拒修、仍有待核对告警或修复次数用尽时，如实结束并保留原因。
3. 首个验收用一个单模块 Maven 编码任务和一个行为预期明确、现有检测器能定位的缺陷。在同一任务记录里核对首次告警、针对同一 ID 的只读复核与定位、对应修改、修改后的独立检查和最终状态。另用一条证据不足的告警验证不会据此改代码或通过验收。

Case K 等探针用于解决第 ④、⑤ 步实际遇到的解释错误。候选补丁工作归入第 ⑥ 步，benchmark 用于评估跑通后的整条循环。以下专项记录与长期发布条件按此优先级安排。

## 当前实现与目标差距

下表记录规格冻结时的基线。后续已增加独立的 [Maven 容器检查](maven-check.md)，包含真实构建、测试、编译产物分析和阶段耗时；聊天 `/check`、模型分析工具与任务结束后的宿主验收已接入同一检查接口，支持 JSON/Markdown 阶段报告。本阶段仍有隔离、注解处理器与定向检测器等验收项未完成。

agent 结果已迁移到 `schemaVersion: 2`：测试失败或未运行时不能以旧 `verified` 放行，构建与测试错误按修复策略处理。Maven 不可用时不回退宿主 javac；手动 `/check` 不创建模型会话、基线、复核或修复循环。当前已实现每轮模型任务默认采集修改前基线，并在 JSON/Markdown 报告中描述项目告警的新增、消失、延续和变化；基线失败保留证据且允许原任务继续，环境不一致不给增减数字，比较不免除既有告警或测试失败。

基础 [只读复核](review.md) 已提供显式单告警入口：向无工具的独立模型请求发送报告中已记录的局部证据，另存 E1 建议，不修改检查状态或自动处置。它不读取当前源码、不核验当前工作区版本，也不具备完整调用关系或多路径取证。SQL 小规模探针已完成两轮开发验证及一次冻结提示的 held-out 验证；仅实验脚本补充了匹配历史快照的相关源码与策略，尚未接入聊天。新六例分类全部正确，但只有三份解释全部事实获支持，路径推理仍有缺口。当前输入失效检查、人工处置及隔离候选补丁保留在后续路线中，日常自动取证与自动排除继续暂缓。

## 专项记录：SQL 注入告警复核能力探针

2026-11-03 参考用户提供的 `nextstep.md` 调整近期优先级。目标是判断模型能否利用 Tai-e 证据提出有依据的误报建议，同时保留真实缺陷并在关键证据缺失时弃权。本步为开发用能力验证，不作为正式 benchmark 成绩或成本改善结论；原产品权限边界和发布验收要求不变。

现有 `taint-buggy` / `taint-clean` 是自定义 source/relay/sink 信息流样例，sink 调用 `println`；它们验证污点与证据导出链路，不等于 SQL 注入能力已通过验收。

按最小步骤执行：

1. **先建立 SQL 案例与实际告警矩阵。** 固定 JDK、Tai-e JAR、入口、依赖和 source/sink/transfer/sanitizer 策略，使用隔离的单模块 Maven 小项目。先取得真实报告与失败原因，再选择复核输入。首批目标为一条真告警、一条确实被报告且可独立证伪的误报告警，以及一个关键证据缺失的复核视图。第三项可以复用前两项的代码，仅限制模型可见证据；证据充分性与程序真值分开记录。
2. **独立建立判断依据并隐藏标签。** 真缺陷提供能触发错误 SQL 行为的执行证据；误报提供固定前提下覆盖告警全部相关可能性的代码/数据流论证。测试未复现不能代替误报证明。模型看不到标签、期望答案、泄漏结论的目录名或注释。所有候选及运行结果保留；无告警的安全案例是阴性对照，不能记为模型排除了误报。没有找到可证伪的实际误报时如实记录，不修改规则来硬凑预期结果。
3. **按案例补必要证据。** 优先考虑同一分析版本的完整相关方法、必要调用和具体污点策略；入口、分支条件或 sanitizer 定义仅在案例需要时补充。固定证据版本并记录缺失项；不先建设通用业务契约系统、大型取证平台或新的复杂分类体系。
4. **固定条件运行复核并逐条核验。** 使用既有无工具复核入口、固定模型/提示和预算，分别记录原始模型建议、宿主规范化结果、证据依据及其是否成立。单条摘要路径不可行不能排除其他可行路径；人工处置保持待定，实际项目告警不自动关闭。记录误报建议、真告警被误判为误报、正确保留、弃权和失败的原始数量，并记录全部调用 token、耗时及实际人工投入；小样本不外推准确率或提效。

首个交付物是**案例—独立依据—真实 Tai-e 告警矩阵**，随后才是逐条复核对照表和可复跑脚本。里程碑的成功条件是至少展示有依据的误报区分、真实缺陷保留及证据不足弃权；没有达到时保留失败结果，按具体缺口决定继续补证据还是调整方案，而非仅凭流程跑通宣称完成。首轮未达到目标，第二轮已观察到所选视图的分类目标及有依据的核心推理，附加解释仍有错误；以下阶段验收勾选不因开发探针结果而改变。

2026-11-03 实测：4 个真实 H2/JUnit 测试通过；输入拼接 A 报告 1 条真告警，上下文合并 B 与互斥分支 C 各报告 1 条可依据完整代码证伪的告警，固定查询 D 无告警。随后固定模型与提示执行 3 次独立请求：A 完整视图保留真告警；B 完整视图识别了核心原因，但多余字段导致协议拒收，且列出不适用的缺失证据；B 缺实现视图仍按方法名猜测并建议误报，由宿主降为 `unknown`，未达到模型主动弃权目标。所有原报告和告警保留，未重试刷答案。详见 [SQL 探针](sql-probe.md) 和 [首轮结果解读](../.taie-agent/sql-review-probe/2026-11-03T10-54-40-266Z-ef9cf25c/interpretation.md)。

第二轮完成了提示版本 2 和 E/F 同形调用对照：E 的 helper 保存首次输入、F 只返回当前参数。真实构建与 6 项 JUnit 通过，A/B/C/E/F 各有 1 条告警，D 无告警。七次独立 DeepSeek 请求均格式有效：完整 A/E 保留真告警，完整 B/F 提出疑似误报，B/E/F 部分视图主动返回 `analysis_incomplete`；无宿主降级、无重试、无真告警误排建议。原检查仍保留 5 条告警。E 部分视图本身含字段存取证据，API 前预定目标允许保留疑似真告警或弃权，未裁剪原路径。[第二轮逐条解读](../.taie-agent/sql-review-probe/2026-11-03T11-17-31-044Z-44db6a55/interpretation.md) 记录了 B/F 部分视图误读表达式、F 完整视图误称 Main 未提供等解释问题。

随后按用户要求冻结版本 2，在未参与提示调优的 G–L 六个新案例上完成 [held-out 验证](sql-heldout.md)：多分支、区间、循环别名、数组索引、switch 穿透和 finally 覆盖均取得真实告警。6 次分类全部正确，但 116 项去重事实中有 4 项错误，只有 3/6 份解释全部获支持；G/I/K 均属于分类对而路径解释错。关键事实获支持 14/18。事实评分为待人工复验的 agent-assisted 记录，不是独立人类标注。该轮没有改提示、没有重试、没有自动排除告警。

2026-11-17，用户委托 AI 完成六例的复核与标注。独立源码论证及 54 条 H2 边界观测确认原分类；补齐旧 K17 的复合句抽取后，去重事实评分仍为 112/116。另立 v3 实验版本，沿用同一证据执行六次真实模型请求：分类 6/6，全部事实获支持的解释由 3/6 降为 1/6，关键事实仍为 14/18，未通过预设质量门槛。v3 保留为失败回归，不替换日常版本；旧冻结内容和报告未改。详见 [受委托复核与 v3 回归](sql-regression-v3.md)。

源码引用功能已按调整后的方式实现：宿主为固定快照生成片段编号，模型按解释项引用编号，报告由宿主展开文件、行范围与原文。新增独立单案例入口，尚未接入日常 `/review`。案例 J 的一次真实请求引用 4 个不同编号，全部匹配；另观察到一处赋值顺序误述，因此引用结果明确保持 `semantics: not_checked`。类型检查及 154 项宿主测试通过，1 项环境跳过。详见 [源码引用实现与实测](source-citations.md)。

单方法执行顺序校验已完成第一步：真实 Tai-e 导出 CaseJ.execute 的 18 个节点和 18 条普通控制流边，两条正确序列通过，颠倒赋值和跨分支拼接被拒绝。一次真实模型请求给出的两条完整序列也通过，报告由宿主展示实际顺序。类型检查及 160 项宿主测试通过，1 项环境跳过。[实现、命令与证据](control-flow-review.md)。当前只证明提交序列的结构连接，条件可满足性、值流和全路径覆盖仍未检查。

**探针后续：** K 的 switch 穿透与后置覆盖可用于检验第 ④、⑤ 步的路径判断，分别记录控制流连接、分支条件和 sink 前最后写入。G–L 用作开发回归，稳定后另备新 held-out 集。日常 `/review` 自动取证与自动排除继续暂缓，分类正确、事实可靠与完整论证覆盖分别验收。本次 AI 标注已完成，`humanReviewed: false`。

## 阶段一 单模块 Maven 与隔离执行

交付目标：在 JDK 17 和一种受验收的隔离环境中，对单模块 Maven 项目完成真实构建、项目测试、Tai-e 全量分析与证据记录。这一阶段不扩充检测器，也不开展最终模型比较。

主实现路线为 Linux 容器和固定工具链。Windows 使用 Docker Linux 容器后端；先检查后端能否运行并满足隔离要求，再发布支持声明。调查时本机存在 Docker CLI 29.8.0、WSL 2.7.12.0 和 Microsoft JDK 17.0.20.1，PATH 上 Java 为 21.0.5，Maven 不在 PATH；这些事实不证明容器引擎或隔离可用。宿主无需另外安装 Maven，目标运行环境提供固定版本。

实施顺序：

1. 诊断容器后端、JDK 17 和历史 Java 超时，记录按构建、适配器编译、Tai-e 启动与分析分解的耗时。
2. 引入独立的执行后端接口。工作目录来自项目快照；资源、网络、超时和取消由宿主控制，外部模型调用与项目执行分离。
3. 接入 Maven 的真实编译和测试流程，取得有效依赖、产物、源码映射及注解处理信息。拒绝当前范围外的多模块输入并给出原因。
4. 让 Tai-e 消费同一输入快照的真实产物和 classpath，记录 JDK、标准库、依赖、构建配置和生成代码的对应关系。
5. 输出分阶段结果和诊断，接入 CLI 设置与帮助，保留现有独立分析入口及明确的原型兼容路径。

验收证据：

- [ ] 干净的支持环境可按文档构建运行镜像，并完成无需模型的项目构建、测试与分析。
- [x] 带第三方依赖的单模块项目实际解析依赖并编译；报告列出所用依赖和产物。2026-11-03 的 Commons Lang / JUnit 案例已验证，见 [验证记录](validation.md)。
- [ ] 带注解处理器的项目真实生成并使用代码；生成代码展示过滤不破坏业务代码的分析关系。
- [ ] 测试通过、测试失败、无测试、构建失败、依赖不可用、分析失败均返回不同的阶段证据。
- [ ] 使用 JDK 17 完成检测器定向回归和 SQL 注入正反例分析，分别记录实际运行 JVM 与被分析运行库。
- [ ] 禁止项目读取项目快照以外的宿主哨兵文件、密钥和容器管理接口；受限网络与资源策略有可重现检查。
- [ ] 超时或取消终止项目子进程，保留日志与部分结果；隔离后端不可用时不得执行本机项目命令。
- [ ] 新分析不复用不匹配的旧产物；快照后并行修改被识别为报告过期，不覆盖原项目。
- [ ] 对历史超时有可复现诊断和处置结果；不得仅扩大阈值后宣称根因解决。

## 阶段二 只读复核与受控修复

交付目标：用 SQL 注入作为主要证据链案例，让模型在固定输入上提出可审查建议，并由人类决定告警处置及补丁应用。

实施顺序为修改前基线、分层证据获取、复核状态与审计、隔离候选补丁、批准应用、最终独立验收。证据充分性和工作区保护先于交互体验优化。

- [x] 基础基线可区分新增、消失、变化和延续告警；基线失败有单独状态，独立于修复次数；环境不一致不计算差异。`npm run test:baseline` 使用真实 Java/Tai-e 和脚本确定性修改，不调用模型 API；告警对比不等于修复或误报判定。
- [x] 基础单告警复核入口已实现：固定报告证据包、无工具模型请求、独立 JSON/Markdown 建议、人工处置待定；`npm run test:live:review` 提供真实分析与一次模型请求的检查入口。具体执行结果见 [验证记录](validation.md)。
- [ ] 复核工具不能修改代码、测试、规则和入口，仓库内容或日志中的指令不能改变宿主权限。
- [ ] 同一 source/sink 存在多条路径的案例中，否定一条摘要路径不会自动关闭整条告警。
- [ ] 证据不足时返回无法判断；所有严重等级的模型输出均不能自动关闭告警或放行 CI。
- [ ] 人工处置保留原始报告、理由、证据范围和审核者；相关输入变化使处置依据过期。
- [ ] 批准生成候选后，原工作区保持不变；候选 diff 及其测试和分析结果可审查。
- [ ] 每次应用对应具体已批准补丁，拒绝、EOF 或非交互缺少批准均不应用。
- [ ] 工作区并行修改导致冲突时停止；失败恢复不会覆盖用户已有或随后新增的修改。
- [ ] 补丁修改规则、删除测试、抑制告警或删功能不会仅因告警减少而通过验收。
- [ ] 各阶段结果、CLI 面板和帮助与新协议一致，旧 `verified` 和 `auto` 含义的迁移明确。

## 阶段三 开发集校准与冻结评测

交付目标：确定首版实际支持的项目规模、SQL 注入模式和资源预算，并验证后续实验设计可执行。开发集结果用于工程决策，不作为最终成绩。

| 待冻结项 | 开发集应提供的依据 |
| --- | --- |
| 项目规模 | 源码与字节码规模、依赖数量、构建特征、入口和分析可完成情况。 |
| SQL 注入模式 | source、sink、sanitizer、传播模式、边界和有独立真值的正反例。 |
| 时间与资源 | 冷启动、依赖下载、构建、测试、分析、复核和重试的 P50/P95，CPU、内存及取消表现。 |
| token 与人工预算 | 全部尝试的输入输出 token、缓存口径、费用、人工次数与等待/操作时间。 |
| 成功与风险门槛 | 各任务层的成功定义、成功率、两种误排除风险口径、成本改善要求与统计方法。 |
| 最终评测协议 | 数据和工具版本、划分、标签隔离、各组提示及工具差异、重试和预算、排除条件、完整分母。 |

- [ ] 评分器与独立测试在模型可写范围之外；任务标签、官方补丁和 fixed 版本不可被模型读取。
- [ ] 开发与最终集合按项目/模板家族划分，清理答案线索后任务语义仍可验证。
- [ ] 未标注告警和争议样例不被强制记为误报，指标分母和不适用情况清楚。
- [ ] 明确普通 agent、原始 Tai-e 反馈、Tai-e 加复核三组的公共条件和允许差异。
- [ ] 在首次查看最终测试结果之前锁定规模、预算和验收数值，保留协议版本。

## 阶段四 最终评测与产品发布

按冻结协议运行检测、复核、修复和完整任务评测，保存全部运行、失败和人工介入。报告成功率与资源收益及其波动，不能只选最佳尝试或在看到失败后重写支持范围。

通过产品规格中的发布条件后，才声明相应版本可交付。干净安装、错误恢复、未参与开发的仓库和陌生用户试用属于发布验收。诊断包脱敏、许可证、升级说明和状态协议应随版本交付。

Gradle 接入在 Maven 路径稳定后进行，有限 Spring 模型在 Gradle 之后进入独立里程碑；每次扩大范围都补充模型、案例和完整分母。多模块、动态代理、变量反射、JNI 内部、通用约束求解和自动关闭告警均不在本轮交付范围。
