# Tai-e Coding Agent 开发与验收计划

计划基线：2026-11-03，依据 [已确认产品规格](product-spec.md)。各阶段以可重现证据验收；完成开发事项不自动代表性能目标或发布条件已达到。

## 当前实现与目标差距

下表记录规格冻结时的基线。后续第一步已增加独立的 [Maven 容器检查](maven-check.md)，包含真实构建、测试、编译产物分析和阶段耗时；尚未迁移聊天工具或完成本阶段全部验收项。

| 能力 | 当前实现 | 后续工作 |
| --- | --- | --- |
| 构建 | [taie.ts](../src/taie.ts) 直接执行 `javac -proc:none`，classpath 需显式提供。 | 接真实 Maven 生命周期、依赖与产物发现，感知注解处理器，运行项目测试。 |
| 执行环境 | shell、构建与测试继承宿主权限；修复锁只拦截工具调用。 | 引入隔离执行后端和环境诊断，禁止失败后回退为宿主执行。 |
| 结果验收 | [verification.ts](../src/verification.ts) 在编译与分析完成且无告警时返回 `verified`。 | 分开记录构建、测试、分析、覆盖和复核，版本化迁移结果协议及 CLI 解释。 |
| 复核 | [reporting.ts](../src/reporting.ts) 生成 `triage.json` 模板；宿主未依据复核记录验收。 | 建立只读证据获取、模型建议、人工处置和失效规则。 |
| 污点证据 | [AgentEvidencePlugin.java](../java-adapter/AgentEvidencePlugin.java) 导出 source 相关的最短抽象传播路径。 | 标明路径摘要范围，按需取得更多证据；单路径证伪不能关闭汇总告警。 |
| 修复 | `ask` 获批后允许直接修改原项目。 | 隔离候选、diff 与验证展示、逐次确认应用、冲突检查和安全恢复。 |
| 版本对应 | 已记录源码指纹、分析配置和部分后端版本。 | 完整关联构建输入、依赖、产物、证据、批准与补丁，建立修改前基线。 |
| 评测 | 已有合成案例和真实模型冒烟验证，无比较实验。 | 开发集、独立真值、预算校准、冻结协议及三组比较。 |

已有验证记录中的 Java 耗时问题仍未解决。本计划不把历史通过记录当作新隔离环境或 JDK 17 的验收结果。

## 阶段一 单模块 Maven 与隔离执行

交付目标：在 JDK 17 和一种受验收的隔离环境中，对单模块 Maven 项目完成真实构建、项目测试、Tai-e 全量分析与证据记录。这一阶段不扩充检测器，也不开展最终模型比较。

主实现路线为 Linux 容器和固定工具链。Windows 使用 Docker Linux 容器后端；先检查后端能否运行并满足隔离要求，再发布支持声明。调查时本机存在 Docker CLI 29.8.0、WSL 2.7.12.0 和 Microsoft JDK 17.0.20.1，PATH 上 Java 为 21.0.5，Maven 不在 PATH；这些事实不证明容器引擎或隔离可用。宿主无需另外安装 Maven，目标运行环境提供固定版本。

实施顺序：

1. 诊断容器后端、JDK 17 和历史 Java 超时，记录按构建、适配器编译、Tai-e 启动与分析分解的耗时。
2. 引入独立的执行后端接口。工作目录来自项目快照；资源、网络、超时和取消由宿主控制，外部模型调用与项目执行分离。
3. 接入 Maven 的真实编译和测试流程，取得有效依赖、产物、源码映射及注解处理信息。拒绝当前范围外的多模块输入并给出原因。
4. 让 Tai-e 消费同一输入快照的真实产物和 classpath，记录 JDK、标准库、依赖、构建配置和生成代码的对应关系。
5. 输出分阶段结果和诊断，接入 CLI 设置与帮助，保留现有独立分析入口及明确的原型兼容路径。

验收证据：

- [ ] 干净的支持环境可按文档构建运行镜像，并完成无需模型的项目构建、测试与分析。
- [x] 带第三方依赖的单模块项目实际解析依赖并编译；报告列出所用依赖和产物。2026-11-03 的 Commons Lang / JUnit 案例已验证，见 [验证记录](validation.md)。
- [ ] 带注解处理器的项目真实生成并使用代码；生成代码展示过滤不破坏业务代码的分析关系。
- [ ] 测试通过、测试失败、无测试、构建失败、依赖不可用、分析失败均返回不同的阶段证据。
- [ ] 使用 JDK 17 完成检测器定向回归和 SQL 注入正反例分析，分别记录实际运行 JVM 与被分析运行库。
- [ ] 禁止项目读取项目快照以外的宿主哨兵文件、密钥和容器管理接口；受限网络与资源策略有可重现检查。
- [ ] 超时或取消终止项目子进程，保留日志与部分结果；隔离后端不可用时不得执行本机项目命令。
- [ ] 新分析不复用不匹配的旧产物；快照后并行修改被识别为报告过期，不覆盖原项目。
- [ ] 对历史超时有可复现诊断和处置结果；不得仅扩大阈值后宣称根因解决。

## 阶段二 只读复核与受控修复

交付目标：用 SQL 注入作为主要证据链案例，让模型在固定输入上提出可审查建议，并由人类决定告警处置及补丁应用。

实施顺序为修改前基线、分层证据获取、复核状态与审计、隔离候选补丁、批准应用、最终独立验收。证据充分性和工作区保护先于交互体验优化。

- [ ] 基线可区分新增、消失、变化和遗留告警；基线失败有单独状态。
- [ ] 复核工具不能修改代码、测试、规则和入口，仓库内容或日志中的指令不能改变宿主权限。
- [ ] 同一 source/sink 存在多条路径的案例中，否定一条摘要路径不会自动关闭整条告警。
- [ ] 证据不足时返回无法判断；所有严重等级的模型输出均不能自动关闭告警或放行 CI。
- [ ] 人工处置保留原始报告、理由、证据范围和审核者；相关输入变化使处置依据过期。
- [ ] 批准生成候选后，原工作区保持不变；候选 diff 及其测试和分析结果可审查。
- [ ] 每次应用对应具体已批准补丁，拒绝、EOF 或非交互缺少批准均不应用。
- [ ] 工作区并行修改导致冲突时停止；失败恢复不会覆盖用户已有或随后新增的修改。
- [ ] 补丁修改规则、删除测试、抑制告警或删功能不会仅因告警减少而通过验收。
- [ ] 各阶段结果、CLI 面板和帮助与新协议一致，旧 `verified` 和 `auto` 含义的迁移明确。

## 阶段三 开发集校准与冻结评测

交付目标：确定首版实际支持的项目规模、SQL 注入模式和资源预算，并验证后续实验设计可执行。开发集结果用于工程决策，不作为最终成绩。

| 待冻结项 | 开发集应提供的依据 |
| --- | --- |
| 项目规模 | 源码与字节码规模、依赖数量、构建特征、入口和分析可完成情况。 |
| SQL 注入模式 | source、sink、sanitizer、传播模式、边界和有独立真值的正反例。 |
| 时间与资源 | 冷启动、依赖下载、构建、测试、分析、复核和重试的 P50/P95，CPU、内存及取消表现。 |
| token 与人工预算 | 全部尝试的输入输出 token、缓存口径、费用、人工次数与等待/操作时间。 |
| 成功与风险门槛 | 各任务层的成功定义、成功率、两种误排除风险口径、成本改善要求与统计方法。 |
| 最终评测协议 | 数据和工具版本、划分、标签隔离、各组提示及工具差异、重试和预算、排除条件、完整分母。 |

- [ ] 评分器与独立测试在模型可写范围之外；任务标签、官方补丁和 fixed 版本不可被模型读取。
- [ ] 开发与最终集合按项目/模板家族划分，清理答案线索后任务语义仍可验证。
- [ ] 未标注告警和争议样例不被强制记为误报，指标分母和不适用情况清楚。
- [ ] 明确普通 agent、原始 Tai-e 反馈、Tai-e 加复核三组的公共条件和允许差异。
- [ ] 在首次查看最终测试结果之前锁定规模、预算和验收数值，保留协议版本。

## 阶段四 最终评测与产品发布

按冻结协议运行检测、复核、修复和完整任务评测，保存全部运行、失败和人工介入。报告成功率与资源收益及其波动，不能只选最佳尝试或在看到失败后重写支持范围。

通过产品规格中的发布条件后，才声明相应版本可交付。干净安装、错误恢复、未参与开发的仓库和陌生用户试用属于发布验收。诊断包脱敏、许可证、升级说明和状态协议应随版本交付。

Gradle 接入在 Maven 路径稳定后进行，有限 Spring 模型在 Gradle 之后进入独立里程碑；每次扩大范围都补充模型、案例和完整分母。多模块、动态代理、变量反射、JNI 内部、通用约束求解和自动关闭告警均不在本轮交付范围。
