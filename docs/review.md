# 单告警只读复核

当前提供一个显式调用的最小复核流程：把已保存检查中的一条项目告警交给独立模型请求，取得有依据范围的建议，再另存中文报告。它不自动修改代码、关闭告警、接受风险或改变质检结论。

## 使用方式

聊天中先检查项目，再从命令行告警摘要、`check.md` 或 `check.json` 取得告警 ID：

```text
/check
/review <项目告警ID>
```

`/review` 使用当前会话最近一次手动检查或模型任务的最终宿主检查。切换项目后需要重新检查。仅构建与分析已经完成的项目告警可用；项目测试失败不会禁止解释告警，但失败状态继续保留。依赖告警、没有告警的结果以及构建/分析未完成的结果不能通过该入口复核。

独立复核已保存的统一检查报告：

```powershell
npm start -- review --project examples/playground --report "<check.json绝对路径>" --finding "<项目告警ID>"
```

这里应提供统一的 `check.json`，而非后端 `report.json`。`--report` 的相对路径以启动目录为准；报告必须属于 `--project` 指定项目。可以用 `--provider`、`--model`、`--timeout` 设置模型和请求时限，聊天中则沿用对应会话设置。

每次显式调用会发送一条告警的记录证据并产生正常模型 API 用量；不会在每轮编码后自动运行。`/analysis off` 不影响显式复核，`/review` 不消耗已预定的 `--skip-taie` 或 `--no-repair`。命令不重新运行 Java/Tai-e，不进入修复循环，Ctrl+C 可取消当前请求。

## 模型可以看到什么

宿主从指定检查报告中提取告警、记录时的源码片段/污点证据、构建与测试阶段结果及分析限制，并将实际发送的证据包保存到新目录。模型请求没有文件、shell、编辑或其他工具，也不沿用编码对话历史、项目指令或扩展。代码、注释和日志中的文本仅作为证据数据。

第一版没有额外读取当前源码、调用者/被调方法、字段和别名关系、检测器实现或其他传播路径。缺失信息须明确记录，不能用模型推测补成事实。证据包中的 `finding`、`check`、`context` 是引用标识，不是证明强度等级。

复核绑定的是报告记录的输入版本：`applicability: recorded_input_only`、`currentWorkspace: not_checked`。修改了当前源码、规则或会话配置后，旧复核不会自动标成过期；需要判断当前状态时，先重新检查，再复核新报告。`stale` 仅表示复核期间原始检查报告本身发生了变化或不可读取，不表示已实现完整的当前输入失效检查。

## 建议与人工处置

所有模型建议统一标为 `E1_model_explanation`，人工处置为 `pending_human`。本版尚无确认误报、接受风险或批准处置的命令。

| `assessment` | 含义 |
| --- | --- |
| `true_positive` | 模型认为可能是真实缺陷；中文报告显示“疑似真实缺陷” |
| `suspected_false_positive` | 疑似误报，尚未得到独立证明或人工确认 |
| `accepted_risk` | 建议人工评估是否接受风险；这个名称不表示用户已经接受 |
| `out_of_scope` | 建议归为范围外，与误报分开 |
| `analysis_incomplete` | 分析或证据不完整 |
| `unknown` | 无法判断 |

每条建议必须说明规则主张、判断依据、证据引用、覆盖范围、适用前提与缺失证据。模型不能新增“已关闭”“已批准”等权限字段。响应格式无效、请求错误或取消会记录为失败，而非构造成功建议。

复核提示版本 `2` 要求先判断证据是否足以支持结论。辅助方法的名称、签名或返回值被丢弃，不能证明其实现或无副作用；缺少决定性实现时应返回 `unknown` 或 `analysis_incomplete`，覆盖范围为 `insufficient`。`missingEvidence` 只列阻碍结论的关键缺口；完整静态代码已支持的论证，不必把可选运行轨迹列为必要证据。测试计数和文件名也不能用来推断测试内容。

响应仍严格使用原有八个字段；`analysis_incomplete` 是 `assessment` 的枚举值，不是新增布尔字段。提示改进不保证模型遵守协议，宿主仍拒收多余字段并保留原始回复，不通过删字段或重试来伪造成功。

证明一条最短抽象污点路径不可行，不代表同一 source/sink 的其他路径也不可行；测试通过或未复现，同样不能证明整个告警为误报。模型若提出疑似误报，但只覆盖单路径、声明有缺失证据或未引用告警证据，宿主将结构化建议保留为 `unknown`，原始模型响应另存。即使模型声称覆盖整条告警，结果仍只是 E1 建议，不经过自动证明，不会关闭告警。

## 报告与状态

每次运行创建 `.taie-agent/reviews/<运行ID>/`：

- `request.json`：实际系统提示、提示版本与 SHA-256，以及发送的证据包。
- `review.json`：输入报告 SHA-256、证据包摘要、来源指纹、提示版本与 SHA-256、模型响应与用量、结构化建议、诊断及限制。旧结果缺少提示版本字段时保持原样。
- `review.md`：中文建议、判断依据、适用范围及证据入口。

原始 `check.json`、`check.md` 和后端报告不变。检查记录中的 `stages.review: not_run` 保留检查当时的状态，之后完成的单告警复核另存关联记录。`affectsCheckStatus: false` 表示所有告警继续保留，测试失败及其他验收状态不被复核覆盖。

| 复核 `status` | 含义 | 独立命令退出码 |
| --- | --- | ---: |
| `completed` | 取得格式有效的建议，仍待人工处理 | 0 |
| `failed` | 请求、取消或响应解析失败 | 1 |
| `stale` | 复核期间原始检查报告变化或不可读取，建议不可用于处置 | 1 |

退出码 0 只表示复核操作完成，不代表代码质检通过。输入报告、告警 ID 等前置条件不合法时直接报错，不发起模型请求。`--json` 或聊天 `/set json on` 将结果 JSON 写入 stdout，提示保留在 stderr。

## 验证与后续范围

```powershell
npm run typecheck
npm run test:host
npm run test:live:review
```

`test:live:review` 运行真实 Java/Tai-e 并发起一次模型请求，属于基本链路验证；执行结果见 [验证记录](validation.md)。它不替代误报识别 benchmark、多路径污点复核、证明充分性或人工处置验收。

后续工作包括按需取得更多固定版本证据、自动检查相关输入变化、保存可审计人工处置，以及独立的候选补丁和批准应用流程，见 [开发计划](development-plan.md)。
