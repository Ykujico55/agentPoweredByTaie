# 冻结提示后的 held-out 验证口径

本轮执行用户指定的分类与解释事实双重验证，不修改当前 v2 提示、解析器、模型调用设置或日常 `/review`。固定内容见 `protocol.json`；新数据、独立 oracle 与实验执行脚本在模型请求前写入 `dataset-lock.json`。本文件也随数据锁定。

## 数据与运行

六个新编写的合成案例 G–L 未用于 v2 提示调整，分别涉及多分支传播、数值区间、循环和别名、数组索引、switch 穿透、finally 覆盖。它们是相对于提示调优隔离的数据，并非代表真实项目分布的外部 benchmark。条件固定后，每条实际 Tai-e 项目告警只请求一次独立无工具模型，不看答案挑样本、不重试或修改提示。

oracle 在看模型回复前由完整源码和独立 SQL 执行建立。测试通过可能意味着成功复现漏洞；安全结论须覆盖全部相关输入/路径，不能由有限测试未复现得出。所有实际告警、未报告案例、构建/分析/请求失败均保留。每个案例按预先定义的 source/sink 判断，多个告警不得冒充多个独立程序。

## 分类

- 主指标：格式有效且与真值相符的二分类数 / 全部实际可复核目标告警数。`unknown`、`analysis_incomplete`、其他分类、格式失败、请求失败和过期响应留在分母。
- 原始建议和宿主规范化分别记录。仅原始文本出现正确标签、但协议无效，不算成功分类。
- 辅助指标：二分类覆盖率、仅在有效二分类上的条件正确率、真/误报混淆矩阵、真告警被建议排除的数量。
- 六个计划案例中的未报告案例单列；没有告警不能当作模型正确识别，也不能伪造一条告警让模型复核。分母为零时显示 N/A。

## 解释事实

对原始回复的 `ruleClaim`、`rationale`、`assumptions` 和 `missingEvidence` 中所有具体、可核对的事实主张逐项摘录。同一回复内重复表达同一事实只计一次；复合句中可独立真假的事实分开。不得只抽取正确事实或只抽取错误事实。分类标签本身不重复算解释事实。

每项保留原文引用、核对后的主张、类别和代码/策略/实际输入的证据位置：

| 类别 | 示例 |
| --- | --- |
| method_or_binding | 引用哪个方法、调用目标是否精确绑定 |
| value_or_side_effect | 哪个值被丢弃、赋值/覆盖/字段副作用是什么 |
| line_or_location | 所称行号或语句位置是否一致 |
| interprocedural_or_path | 调用、跨调用传值、分支条件和整条告警范围 |
| evidence_or_policy | 哪些文件实际提供、source/sink 策略、测试内容是否可见 |

判定使用 `correct`（获证据支持）、`incorrect`（与证据矛盾）、`unsupported`（证据未支持其断言）、`unverifiable`（有争议或无法裁定）。无依据不直接等于已证明为假，四项数量分开报告。把缺失实现当事实、把抽象路径当具体执行、声称未见测试的覆盖情况都须核对，不能藏在 assumptions 中免评。

- 已核实事实正确率：correct / 所有抽取主张；另外报告仅已裁定主张上的 correct / (correct + incorrect)。
- 回复级全部事实获支持率：至少有一项可核对事实且全部为 correct 的有效回复 / 全部计划复核请求。失败、没有解释、没有事实或尚未核对的回复不能算通过。
- 分类别报告事实数量与正确率。没有引用行号时，行号指标为 N/A，不能记作全对。
- 列出 oracle 预定关键事实的覆盖数量。没有谈到关键路径属于解释不充分，不能因为少说事实获得“完整解释正确”的结论；遗漏与错误分开计数。
- 单独列出分类正确但含 incorrect/unsupported 的回复；尚未裁定、关键论证遗漏分别列出，不混称为已证明错误。

事实核对是 agent-assisted、provisional 的源码审阅，附原文与证据供人复核；不是独立人类标注、自动语义证明或人工批准。分歧不强行判正确。所有指标描述本次小集合，不用于自动关闭告警或产品放行。

## 交付与边界

保存完整交互、运行与版本指纹、分类计数、逐条事实核对和中文报告。原始检查与告警不改写。本轮不把新结果用于提示调优；下一轮如需改进，必须另立版本，并把本集合视为已用过的开发证据。
