# Tai-e Java adapter

Compile `TaieAgentExporter.java` and `AgentEvidencePlugin.java` together against the selected Tai-e JAR. The exporter invokes the real `pascal.taie.Main` entry point and serializes analysis result objects as schema version 2 JSON. Arguments are the raw JSON output path, comma-separated host profile IDs, then ordinary Tai-e CLI arguments.

For the `taint` host profile, run actual `pta` with the built-in `TaintAnalysis` plugin enabled through `taint-config`, plus our `pascal.taie.analysis.pta.plugin.taint.AgentEvidencePlugin` in the PTA `plugins` list. Our plugin receives the actual solver lifecycle callbacks and reads its final result. It never adds points-to facts or changes propagation. The package matches Tai-e's taint package because its source/sink point types are package-private in the pinned upstream release.

The exporter reads `TaintFlow` results and finds a shortest propagation path in the actual `ObjectFlowGraph`, retaining only nodes whose computed points-to sets contain taint objects from that flow's source. Every reported edge is a real graph edge. Context collapse can merge executions: the path is an abstract propagation witness, not proof of a feasible execution or exploit. If the graph does not expose a matching path, `path` is empty and `pathStatus` is `unavailable`. Source and sink locations still come from the real flow. Missing bytecode line numbers are omitted, including parameter declaration lines; no line is inferred from model text or DOT files.

The example projects under `examples/taint-buggy` and `examples/taint-clean` use the same explicit demonstration source/sink policy. The buggy sink receives the source through an interprocedural relay; the clean sink receives only a fixed constant. Both deliberately set `taintImplicitEntries: false` to keep demos and integration tests small. This disables implicit JVM entry modeling and can reduce coverage. The host's default remains `true`; the adapter preserves this configuration in analysis metadata/reports.
